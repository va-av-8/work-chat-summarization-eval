# Structured Summarization and Evaluation of Real-World Work Chats

This repository contains the code and experimental setup for evaluating **structured summaries of real-world work chat conversations** generated by large language models (LLMs).

The project focuses on **evaluation rather than model training** and investigates how different LLMs behave when generating task-oriented summaries with an explicit structure.  
It was developed as a final project for an NLP course and is based on real-world work communication scenarios.

---

## Overview

Work chat conversations (e.g., Telegram, Slack) are noisy, informal, and fragmented.  
Important outcomes such as decisions, action items, and open questions are often scattered across multiple short messages.

This project formulates chat summarization as a **structured generation task**, where each summary explicitly separates:
- conversational **Context**,
- **Decisions** made in the discussion,
- **Action items** (optionally with assignees and deadlines),
- unresolved **Questions**.

The main contribution of the project is a **diagnostic evaluation framework** that combines:
- component-wise automatic metrics, and
- judge-based scoring using an LLM evaluator.

---

## Dataset

### Source
- Anonymized fragments of real-world internal work chats.
- Chats are split into fragments of 20 consecutive messages to reflect realistic discussion units.

### Characteristics
- Short, informal, and noisy messages.
- Many fragments contain limited or no actionable content.
- The dataset intentionally reflects real-world conditions rather than curated benchmarks.

### Gold Subset
- A small gold subset (≈30 fragments) is created for evaluation.
- Reference summaries are produced using an **LLM-assisted annotation pipeline**:
  - an LLM generates an initial structured summary,
  - the summary is manually reviewed and corrected.
- The gold subset is used **only for diagnostic evaluation**, not as population-level ground truth.

Raw chat logs are not published due to privacy constraints.  
The repository includes only anonymized samples and scripts required to reproduce the pipeline.

---

## Models

### Summary Generation
The following types of models are evaluated under a unified prompt-based setup:
- **Local open-weight models** (via Ollama),
- **API-based models** with higher capacity.

No fine-tuning is performed. All summaries are generated using the same prompt and fixed JSON output schema.

### Evaluation
Two complementary evaluation approaches are used:
1. **Component-wise automatic evaluation**, measuring:
   - semantic similarity for Context,
   - F1-based overlap for Decisions and Questions,
   - slot-based matching for Actions.
2. **Judge-based evaluation**, where an LLM assigns scores for usefulness, coherence, and faithfulness.

An aggregated **overall automatic score** is reported as a weighted combination of component-level metrics and used as a diagnostic indicator.

## Running the Project

### 1. Install dependencies
```bash
pip install -r requirements.txt
```

## 2. Configure environment

- Copy .env.example to .env
- Add required API keys (if using API-based models)

## 3. Run experiments

Use the notebooks in notebooks/ to:
- generate summaries,
- compute automatic metrics,
- run judge-based evaluation,
- reproduce tables from the report.

## Notes

- The project is designed for comparative and diagnostic evaluation, not for training or benchmarking at scale.
- Results should be interpreted as model behavior analysis under a controlled setup, not as absolute performance estimates.
- The codebase is modular and can be adapted to other structured summarization tasks.
